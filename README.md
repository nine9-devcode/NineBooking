# NineBooking

ระบบจองสินค้าออนไลน์พร้อมหลังบ้านครบวงจร — ลูกค้าเลือกสินค้า ใส่ตะกร้า แล้วส่งใบจอง ฝั่งผู้ดูแลระบบจัดการสินค้า ติดตามสถานะใบจอง ออกใบเสนอราคาเป็น PDF ตอบเรื่องแจ้งปัญหา และดูรายงานสรุปยอด

## ที่มาของโปรเจก

โปรเจกนี้พัฒนาต่อยอดจากระบบจองสินค้าที่ผมเขียนให้บริษัทช่วงฝึกงาน

ตัวระบบเดิมทำงานได้จริงและมีฟีเจอร์ครบ แต่ผูกกับบริการภายนอกที่มีค่าใช้จ่ายและบัญชีของบริษัทหลายตัว (บริการเก็บไฟล์ ระบบส่งอีเมล ระบบส่ง OTP ผ่าน SMS) รวมถึงมีข้อมูลบริษัทจริงฝังอยู่ในโค้ด จึงเปิดเป็นสาธารณะไม่ได้

**NineBooking คือเวอร์ชันที่รื้อใหม่ให้เปิดเป็นโอเพนซอร์สได้** โดยยึดหลักว่า _ใครโหลดไปก็ต้องรันได้ทันทีโดยไม่ต้องสมัครบริการอะไรเลย_

สิ่งที่ทำในการรื้อครั้งนี้:

| เดิม                                                        | ใหม่                                                                   |
| ----------------------------------------------------------- | ---------------------------------------------------------------------- |
| เก็บไฟล์บนบริการคลาวด์ (เสียเงิน)                           | เก็บลงดิสก์ในเครื่องผ่าน storage layer ที่สลับ adapter ได้             |
| ส่งอีเมลผ่านผู้ให้บริการภายนอก (ต้องมี API key)             | เขียนอีเมลเป็นไฟล์ `.html` ลง `.dev-outbox/` เปิดดูในเบราว์เซอร์ได้เลย |
| ยืนยันตัวตนด้วย OTP ผ่าน SMS (คิดเงินรายข้อความ)            | ตัดออก — ลืมรหัสผ่านใช้ลิงก์แบบ token แทน                              |
| ล็อกอินผ่าน Google / Facebook (ต้องสมัคร app)               | เหลืออีเมล + รหัสผ่าน ใช้ได้ทันที                                      |
| ตั้งค่าฐานข้อมูลเอง                                         | `docker compose up -d` แล้วมีข้อมูลตัวอย่างพร้อมใช้                    |
| ชื่อ/ที่อยู่/เลขผู้เสียภาษีของบริษัทจริงในโค้ด              | ข้อมูลสมมติทั้งหมด แก้ได้จากหน้าตั้งค่า                                |
| ธีมสว่างหน้าบ้าน + เทาเข้มหลังบ้าน (สีฝังในโค้ด ~2,900 จุด) | ธีมน้ำเงินเข้มทั้งระบบผ่าน design token ชุดเดียว                       |
| ไฟล์กระจายตาม `components/` `hooks/` `types/`               | จัดกลุ่มตาม feature ใน `src/features/`                                 |

> โปรเจกนี้ทำขึ้นเพื่อแสดงผลงานและการเรียนรู้ ข้อมูลสินค้า ราคา และคำสั่งจองทั้งหมดเป็นข้อมูลตัวอย่าง

## เริ่มใช้งาน

ต้องมี **Node.js 20+** และ **Docker**

```bash
git clone https://github.com/nine9-devcode/NineBooking.git
cd NineBooking
cp .env.example .env
npm install
npm run setup
npm run dev
```

เปิด http://localhost:3000

`npm run setup` จะสร้างฐานข้อมูลด้วย Docker แล้วใส่ข้อมูลตัวอย่างให้ (สินค้า 15 รายการ ใบจอง 5 ใบ ใบเสนอราคา 2 ใบ เรื่องแจ้งปัญหา 3 เรื่อง และยอดเข้าชมย้อนหลัง 90 วัน เพื่อให้กราฟในหน้ารายงานมีข้อมูล)

## ฟีเจอร์

**ฝั่งลูกค้า**

- เลือกดูสินค้าตามหมวดหมู่ (รองรับหมวดหมู่ซ้อนกัน) และค้นหาด้วย full-text ของ PostgreSQL — จัดอันดับตามความเกี่ยวข้อง และทนคำสะกดผิด ("กลอง" ก็เจอ "กล้อง")
- ระบบจับคู่สินค้า — เลือกกล้องแล้วระบบเสนออุปกรณ์ที่ใช้ร่วมกันได้ กำหนดได้ทั้งระดับหมวดหมู่และเจาะจงรายสินค้า
- ตะกร้าสินค้า ส่งใบจอง และติดตามสถานะ
- แจ้งปัญหาพร้อมแนบรูป และดูประวัติเรื่องที่แจ้ง
- กระดิ่งแจ้งเตือนเมื่อสถานะใบจองหรือเรื่องที่แจ้งเปลี่ยน
- ดูใบเสนอราคาที่เจ้าหน้าที่ส่งมา กดยอมรับหรือปฏิเสธได้เอง พร้อมดาวน์โหลดเป็น PDF

**ฝั่งผู้ดูแลระบบ**

- จัดการสินค้า หมวดหมู่ และการจับคู่ พร้อมตัวแก้ไขข้อความแบบ rich text
- จัดการใบจอง เปลี่ยนสถานะตามกฎที่กำหนดไว้ (ใบที่เสร็จสิ้นหรือยกเลิกแล้วย้อนกลับไม่ได้) และบันทึกหมายเหตุ
- ออกใบเสนอราคาเป็น PDF ภาษาไทย รองรับการทำหลายเวอร์ชันของใบเดียวกัน
- รับเรื่องแจ้งปัญหาและตอบกลับลูกค้า
- รายงานสรุปยอด — กราฟยอดจอง สินค้ายอดนิยม สัดส่วนตามหมวดหมู่ ส่งออกเป็น Excel และ PDF
- แจ้งเตือนแบบเรียลไทม์ผ่าน Server-Sent Events เมื่อมีใบจองหรือเรื่องแจ้งปัญหาใหม่
- ประวัติการใช้งานระบบ — บันทึกว่าใครแก้ข้อมูลอะไรเมื่อไหร่ กดค่าในตารางเพื่อกรอง และค้นด้วยเลขที่เอกสารได้
- เครื่องมือระบบสำหรับผู้ดูแลระบบสูงสุด — ดูจำนวนข้อมูลแต่ละตาราง สั่งรันงานตามเวลาเอง และล้างข้อมูลที่โตเรื่อยๆ (ทุกการกระทำถูกบันทึกลงประวัติ)
- ปิดเว็บชั่วคราวเพื่อปรับปรุงระบบได้จากหลังบ้าน

**ความปลอดภัย**

- รหัสผ่านเข้ารหัสด้วย bcrypt (cost 12)
- จำกัดอัตราการเรียกทั้งต่อบัญชีและต่อ IP ครอบคลุมล็อกอิน สมัครสมาชิก ขอลิงก์ตั้งรหัสผ่าน แจ้งปัญหา และอัปโหลดไฟล์
- ลิงก์ตั้งรหัสผ่านใหม่เก็บเป็น hash หมดอายุใน 30 นาที ใช้ได้ครั้งเดียว และไม่บอกว่าอีเมลนั้นมีในระบบหรือไม่
- แยกสิทธิ์ผู้ใช้กับผู้ดูแลระบบทั้งในระดับเส้นทางหน้าเว็บและ API
- ตรวจชนิดไฟล์ที่อัปโหลดจาก magic bytes ของไฟล์จริง ไม่ใช่จากชื่อไฟล์หรือ header ที่ผู้ส่งตั้งเอง
- ไฟล์แนบของลูกค้าเก็บนอก `public/` ต้องผ่านการตรวจสิทธิ์ก่อนถึงจะเปิดได้
- เลขที่เอกสารออกแบบ atomic ในทรานแซกชันเดียวกับเอกสาร จึงไม่ชนกันเมื่อมีคนกดพร้อมกัน

## โครงสร้างโปรเจก

```
NineBooking/
├─ docs/                     # เอกสารอธิบายการทำงานของระบบ
├─ prisma/
│  ├─ schema.prisma          # โครงฐานข้อมูล 25 ตาราง
│  ├─ migrations/
│  └─ seed.ts                # ข้อมูลตัวอย่าง
├─ public/
│  ├─ brand/                 # โลโก้
│  ├─ fonts/                 # ฟอนต์ไทยสำหรับ PDF
│  └─ uploads/               # ไฟล์ที่ผู้ใช้อัปโหลด (ไม่เข้า git)
└─ src/
   ├─ app/                   # เส้นทางหน้าเว็บและ API เท่านั้น ไม่มี business logic
   │  ├─ (public)/           # หน้าที่ไม่ต้องล็อกอิน
   │  ├─ admin/              # หลังบ้าน
   │  └─ api/                # REST API
   ├─ features/              # แบ่งตามงาน แต่ละโฟลเดอร์มี component/hook/schema ของตัวเอง
   │  ├─ auth/  cart/  categories/  dashboard/  notifications/
   │  └─ orders/  products/  quotations/  settings/  support/  users/
   ├─ components/
   │  ├─ ui/                 # ปุ่ม ฟอร์ม ตาราง ที่ใช้ร่วมกันทั้งระบบ
   │  ├─ layout/             # navbar, footer, sidebar
   │  └─ legal/
   ├─ lib/                   # โครงสร้างพื้นฐานที่ทุก feature ใช้ร่วมกัน
   │  ├─ api/                # guard ตรวจสิทธิ์, รูปแบบ response, ตัวอ่าน query
   │  ├─ auth.ts  db.ts  env.ts
   │  ├─ storage/            # จัดการไฟล์อัปโหลด
   │  ├─ mailer/             # ส่งอีเมล (โหมด dev เขียนเป็นไฟล์)
   │  └─ pdf.ts  excel.ts  utils.ts
   ├─ config/                # ค่ากลางของเว็บ ข้อมูลบริษัท สีเอกสาร
   └─ types/
```

**หลักที่ยึด**

- `src/app/` มีแต่เส้นทาง — ตรรกะจริงอยู่ใน `features/` หรือ `lib/`
- แต่ละ feature เก็บของตัวเองไว้ด้วยกัน ไม่ต้องไล่หาข้าม 4 โฟลเดอร์
- `lib/` คือของที่ทุก feature ใช้ร่วมกันเท่านั้น
- สีทุกจุดอ้างจาก design token ใน `src/app/globals.css` ไม่มีค่าสีฝังในคอมโพเนนต์

## คำสั่งที่ใช้บ่อย

```bash
npm run dev          # รันโหมดพัฒนา
npm run build        # build สำหรับใช้งานจริง
npm run typecheck    # ตรวจชนิดข้อมูล

npm run format       # จัดรูปแบบโค้ดด้วย Prettier

npm run db:up        # เปิดฐานข้อมูล (Docker)
npm run db:down      # ปิดฐานข้อมูล
npm run db:seed      # ใส่ข้อมูลตัวอย่างใหม่ (ล้างของเดิม)

npm run db:reset     # ล้างฐานข้อมูลแล้วสร้างใหม่ทั้งหมด
```

ดูข้อมูลในฐานข้อมูลผ่านเบราว์เซอร์ได้ที่ http://localhost:8080 (Adminer มากับ docker compose)

## เรื่องที่ควรรู้ก่อนเอาไปใช้จริง

โปรเจกนี้ตั้งใจให้รันในเครื่องได้ง่ายที่สุด จึงมีบางจุดที่ต้องเปลี่ยนก่อนขึ้นใช้งานจริง

**ไฟล์อัปโหลด** เก็บลง `public/uploads/` ตรงๆ ใช้ได้ดีกับการรันในเครื่องหรือเซิร์ฟเวอร์ของตัวเอง แต่บนแพลตฟอร์มแบบ serverless ไฟล์จะหายเมื่อ deploy ใหม่ — เขียน adapter ตัวใหม่ที่มี `saveFile` / `deleteFile` หน้าตาเหมือนกันใน `src/lib/storage/` แล้วสลับ export โค้ดส่วนที่เรียกใช้ไม่ต้องแก้

**อีเมล** ตัว default เขียนไฟล์ลง `.dev-outbox/` ไม่ได้ส่งออกจริง ถ้าจะต่อ SMTP หรือผู้ให้บริการอีเมล ให้เขียน object ที่ implement `Mailer` ใน `src/lib/mailer/index.ts` แล้วเพิ่มเข้า `DRIVERS` — ระบบจะไม่ยอมทำงานถ้ายังใช้โหมด `outbox` บน `NODE_ENV=production` เพราะลิงก์ตั้งรหัสผ่านใหม่จะไปกองอยู่บนดิสก์

**SEO** ปิดไว้ตั้งใจ — ทั้งรายการสินค้าและหน้าสินค้าอยู่หลังการล็อกอิน (เป็นระบบภายในแบบ B2B) `robots.txt` จึงเป็น disallow ทั้งหมด ถ้าเปิดให้ดูโดยไม่ต้องล็อกอินเมื่อไหร่ ค่อยกลับมาเปิด sitemap กับ Open Graph

**งานตามเวลา** (สรุปยอดเข้าชมรายวัน เก็บกวาด token หมดอายุ) อยู่ที่ `/api/cron` เรียกได้จากตัวตั้งเวลาภายนอกด้วย header `Authorization: Bearer <CRON_SECRET>` หรือให้ผู้ดูแลระบบกดสั่งรันเอง ตัวอย่างสำหรับ Vercel:

```json
{ "crons": [{ "path": "/api/cron", "schedule": "0 17 * * *" }] }
```

**การแจ้งเตือนเรียลไทม์** ใช้ Server-Sent Events ที่เก็บรายชื่อผู้เชื่อมต่อไว้ในหน่วยความจำของ process จึงทำงานได้กับเซิร์ฟเวอร์ตัวเดียว ถ้าจะรันหลาย instance ต้องเปลี่ยนไปใช้ตัวกลางอย่าง Redis pub/sub
